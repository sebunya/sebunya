# Recommendation Engine V2
## Strategic Merchandising Control System

### 1. Executive Overview
The Recommendation Engine provides granular control to dynamically alter product prominence, targeting, and eligibility across disparate platform modules.

*   **V1 Objective**: Fundamental scoring, statistical safety guarantees, and product relevance filters. Protects the shopper experience automatically.
*   **V2 Objective**: Targeted Merchandising Logic. Overlays business mandates on top of V1 distributions. Enables BOOST, SUPPRESS, PIN, and CAMPAIGN injections.

### 2. Operational Guarantees & Safety
V2 is designed as a strictly additive refinement pipeline operating downstream of core recommendation retrieval.
1.  **Fail-Closed Consistency**: If any component of the Rule Application Engine throws an unexpected error, the pipeline implicitly discards the V2 layer and restores the clean V1 candidate dataset perfectly. No recommendations are lost.
2.  **V1 Safety Restoration**: Post-V2 modification, the standard V1 Availability Guard is re-run, ensuring no Merchandising rule can inadvertently pin a product that is currently Out of Stock or Hidden.
3.  **Feature Controlled**: Driven by `RECOMMENDATION_V2_RULES_ENABLED`. System defaults to `false` in production unless explicitly configured to true.

### 3. Rule Processing Order
When multiple intersecting rules impact a single placement, they process sequentially derived by:
1.  **Priority**: Ascending scalar (lower runs first).
2.  **Operation Severity Type**:
    *   **SUPPRESSION** (Strict Elimination) processes FIRST to purge undesirable candidates.
    *   **PINNING** processes SECOND to slot static assets into immutable index rankings.
    *   **BOOSTING & CAMPAIGNS** process LAST by applying weighted scoring scalars to re-sort balance.

### 4. System Administration

#### Routes Registry (API)
Available via `/admin/recommendations`:
- `GET /rules`: Server-side filterable registry.
- `POST /rules`: Mutation persistence (DRAFT vs ACTIVE).
- `GET /rules/:id`: Focused definition inspector.
- `POST /preview`: Isolated async simulation controller (bypasses persistence).

#### Role Based Access Controls (RBAC)
*   **Current Limitation**: Routes temporarily reference `SETTINGS_MANAGE` fallback awaiting full granular token migration.
*   **Migration Ready**: `RECOMMENDATIONS_READ` and `RECOMMENDATIONS_MANAGE` capability constants are provisioned within `@goldplus/shared`. Transition implementation pending permission table reseed.

### 5. Technical Exemptions & Logs
*   **Architecture Exception**: `apps/api/src/interfaces/http/routes/admin/recommendations.ts` houses explicit exemption for dedicated Domain Audit integration. By invoking `IRecommendationRuleAuditRepository` via standard Application UseCases, the recommendation engine bypasses simplistic global log coupling in favor of strict Domain Driven isolation.
*   **Audit Granularity**: Historical artifacts captured for `CREATED`, `UPDATED`, `STATUS_CHANGED`, and `ARCHIVED` state transistions automatically appended to individual rule entities.
