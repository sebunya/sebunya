## How status is derived

Status is computed, never asserted:

- a module with a route file but **no matching mount** is `SOURCE_COMPLETE_NOT_WIRED` — the exact
  defect class that shipped unmounted controlled-activation governance routes;
- a domain with **zero runtime references** and no route, repository, schema or migration is
  `DEAD_OR_DEPRECATED_CONFIRMED`, and must carry both dead-code evidence and a live-capability note;
- anything else with **no test and no PostgreSQL proof** is `WIRED_NOT_TESTED`.

Coverage is counted by files that import the domain directory or reference the module, not by
filename alone — name matching alone under-counted `payments` (23 referencing tests), `quotes` (4)
and `dealers` (2), and would have raised three false gaps.

One genuine gap was found this way and fixed: `fakeReports` is live (port, Drizzle repository and
`ReportFakeProductUseCase`) but had no coverage. `tests/unit/FakeReportDomain.test.ts` now covers
its factory, trimming, anonymous reporting and blank-identity normalisation.

## Validator

Fails on duplicate IDs, invalid or engineering-incomplete statuses, unmounted route modules, dead
status without evidence or with runtime references, missing tests/proofs, missing acceptance method
or rollback dependency, and status totals that do not reconcile. Fault injection confirms it is not
vacuous: forcing a `SOURCE_PARTIAL` status and marking a dead module as referenced were both
rejected, and the file was restored.
